==========================================================================
SCALING ANALYSIS
==========================================================================
Memory-Bound (copy)          : max speedup 1.28x on 8 cores -> efficiency 0.16
Compute-Bound (sin*cos+tan)  : max speedup 4.52x on 8 cores -> efficiency 0.56

Conclusion:
  Kernel A (memory copy) scaled POORLY because it is bandwidth-bound:
  as soon as 2+ cores run, they compete for the same DRAM bus/channels
  and saturate the memory controller. Adding more cores cannot help
  because RAM bandwidth is already the bottleneck (efficiency 0.16).
  Kernel B (sin*cos+tan) scaled BETTER because the transcendental
  math dominates runtime, so cores spend most of their time in ALU,
  not waiting on memory (efficiency 0.56).
